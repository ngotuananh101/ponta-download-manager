# Plan: FDM table layout (uniform background, download table, compact search)

User wants the home screen completely like the FDM screenshot (image-10),
including colors, and the layout when files are present. Two follow-ups:
the background must be uniform (one color), and the search box is not
flush right and is bigger than the buttons.

## FDM reference (image-10, one completed file)

- Title bar: icon + "Free Download Manager", min/max/close.
- Toolbar: checkbox pill, "Newest" pill, "All files" pill, Spacer,
  blue "+ Add download", search pill, menu icon.
- Table header: `# | Name | Size | Status | Download | Upload | Added`
  (muted gray labels, on the same background, no divider).
- One row: checkbox, blue file icon + "pdf-test.pdf", "20.1 KB",
  "Completed" (blue), a `⋮` menu, "0 B/s", "0 B/s", "Today 10:29 PM".
  The row is slightly lighter than the background.
- Below the row, the dashed drop zone still fills the remaining space.
- Status bar: OFF toggle, speeds, HIGH, "Support the project", and the
  file name ("pdf-test.pdf") at the far right.

## Decisions

- **Uniform background.** One dark color for the whole window:
  scaffold, surface (title bar / toolbar / status bar) all `#121212`.
  The toolbar bottom border, status bar top border, and AppHeader
  bottom border are removed, so nothing separates the sections.
  Pills stay slightly lighter (`#2A2A2A`), rows `#1E1E1E`.
- **Table, not cards.** The download list becomes a table with the
  FDM columns. The old ListTile row (name / URL / progress bar /
  inline pause-cancel buttons) is deleted.
  - `#` (40px): the row's selection checkbox (as in the screenshot).
  - `Name` (flexible): blue file icon + file name, ellipsis.
  - `Size` (90px): total size if known, else the downloaded size.
  - `Status` (120px): state name, colored (completed blue,
    downloading green, paused amber, failed red, queued/cancelled
    gray); active downloads also show the percent ("Downloading 45%").
  - `⋮` (36px): row menu (Pause/Resume/Retry/Cancel by state).
  - `Download` (90px): current speed ("0 B/s").
  - `Upload` (90px): always "0 B/s" (PDM does not upload).
  - `Added` (150px): "Today 10:29 PM" / "Yesterday ..." / date.
- **Added needs a timestamp.** `DownloadInfo` (download_api) gains
  a nullable `DateTime? createdAt`; the engine fills it from
  `DownloadRecord.createdAt` (already in the DB); the desktop
  `Download` entity and mapper carry it through. Freezed code is
  regenerated with build_runner.
- **Drop zone always visible.** When files exist, the table sits on
  top and the drop zone fills the rest below it. The rows area is
  capped so the drop zone keeps at least 120px (`LayoutBuilder`).
- **Search box.** Fixed `200 x 36` (same height as the pills and the
  Add button), compact padding, so it is no longer taller than the
  buttons. It stays in the right group (Add, search, menu); the menu
  is the last item, as in FDM.
- **Status bar right side.** The selected file's name (else the
  newest download's) at the far right, muted. Support moves left of
  the spacer.
- **Bulk bar stays.** It is not in FDM, but it is the multi-select
  affordance; removing it is a separate decision.

## Files

- `apps/desktop/lib/shared/theme/app_theme.dart`: uniform FDM scheme.
- `apps/desktop/lib/app/app_header.dart`: drop the bottom border.
- `apps/desktop/lib/features/downloads/presentation/download_table.dart`
  (new): column widths, `formatAdded`, status color/text, size text.
  Pure, unit-tested.
- `apps/desktop/lib/features/downloads/presentation/screens/downloads_screen.dart`:
  table header + rows, `⋮` menu, drop zone below the table, compact
  search, status bar file name, no toolbar/status borders.
- `packages/download_api/lib/src/models/download_info.dart` +
  regenerated freezed/json files: `createdAt`.
- `apps/engine/lib/src/pdm_engine.dart`: `_infoFromRecord` fills it.
- `apps/desktop/.../domain/entities/download.dart` + `data/datasources/download_mapper.dart`:
  carry `createdAt`.
