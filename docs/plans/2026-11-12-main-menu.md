## Current state (code-verified 2026-11-12)

- Toolbar menu: `PopupMenuButton<String>` tooltip 'Menu', 36x36,
  `onSelected: _onMenuSelected`, items pause-all/resume-all only
  (downloads_screen.dart:287-300). `_menuItem<T>` builds a 32px xs
  `PopupMenuItem`. `_onMenuSelected` loops `downloadsActionsProvider`
  (mockable; `WindowService` is NOT read in the screen —
  widget_test.dart has no `windowServiceProvider` override).
- Submenu pattern exists: `_prioritySubmenu` / `_tagSubmenu` — a
  `PopupMenuItem<String>` wrapping a `SubmenuButton` with
  `MenuItemButton`s; onPressed pops the parent popup route
  (`Navigator.of(context).pop()`) then runs the action.
- Export: `exportUrls(Iterable<Download>)` in download_export.dart (one
  URL per line, trailing newline); `saveFileProvider` in
  download_providers.dart (FilePicker saveFile). B2.5 export reads
  `downloadsProvider.value`.
- Add: `DownloadsActions.addDownload(url, {directory, fileName,
  conflictPolicy, paused})` returns `Either<Failure, Download>`; the
  repository validates http(s) first. The single-add screen flow shows
  the conflict dialog on `FileExistsFailure`.
- Clipboard: `Clipboard.getData(Clipboard.kTextPlain)`, mocked in widget
  tests via `mockClipboard(tester, text)`.
- File picking: file_picker ^7.0.2; `directoryPickerProvider` +
  `saveFileProvider` are injectable seams; no pick-a-file-to-open seam
  yet.
- Settings: `FileConflictSettings` (`<data>/pdm/settings.json`, sync
  load/save) holds `fileConflictPolicy` + `recentSaveDirectories`;
  `fileConflictSettingsProvider` is a plain Provider; `load()` re-reads
  the file on every call.
- Quit: `WindowService.quit()` (core/services/window_service.dart)
  stops the engine + IPC host, then closes the window past the tray. Its
  `build()` inits the tray (`TrayIcon.create`) — it must never run in a
  widget test (Gtk SIGABRT headless).
- Version: apps/desktop/pubspec.yaml 0.1.0+1; no package_info_plus dep.

## Decisions

- Bulk add: one helper `_addDownloads(List<String> urls)` in the screen.
  Conflict policy = remembered policy if set, else rename (the safe
  default; bulk never shows the conflict dialog). Loops
  `actions.addDownload`; counts added/failed; snackbar summary: 'Added N
  download(s)' / 'Added N download(s), M failed' / 'No valid URLs found'
  when empty.
- URL parsing: pure `parseUrlList(String text)` — split lines (handles
  \r\n), trim, keep http(s) lines (case-insensitive scheme check),
  dedupe preserving order.
- File reads are sync (`File.readAsStringSync`) — async stalls in a
  widget test's FakeAsync zone.
- Paste from file / Import downloads share one pick-file seam:
  `pickFileProvider = Provider<Future<String?> Function()>` defaulting to
  `FilePicker.platform.pickFiles()` returning the single file's path;
  cancelled → do nothing. Import downloads = read file → parseUrlList →
  `_addDownloads`.
- Export all downloads: `exportUrls(all rows)` +
  `saveFileProvider('downloads.txt')`, sync write, snackbar 'Exported N
  download(s)' (same as B2.5).
- Export settings: build JSON from current values (policy + recent dirs)
  via a new `FileConflictSettings.exportJson()`, save via
  `saveFileProvider('settings.json')`, sync write.
- Import settings: pick file → new
  `FileConflictSettings.importJson(String)` (decode, must be a JSON
  object; policy must be 'overwrite'/'rename' or absent; recent dirs
  filtered to strings; writes via existing `save()` /
  `saveRecentDirectories()`; returns false on invalid input) → snackbar
  ok/invalid. No provider invalidate needed: `load()` re-reads the file
  on every call.
- About: `showAboutDialog` in a new about_dialog.dart (PdmDialog):
  'Ponta Download Manager' + 'Version 0.1.0'. Version const
  `kAppVersion = '0.1.0'` in a new apps/desktop/lib/app/app_info.dart,
  comment: keep in sync with pubspec.yaml version.
- Quit: new `quitAppProvider = Provider<Future<void> Function()>`
  defaulting to
  `() => ref.read(windowServiceProvider.notifier).quit()`; tests override
  it with a recording stub so `WindowService` (tray init) never builds in
  a widget test.

## Parts

- M1: `parseUrlList` + unit tests + this plan doc. Files: new
  apps/desktop/lib/features/downloads/data/services/url_list.dart, new
  test/features/downloads/url_list_test.dart.
- M2: menu restructure + Paste urls from clipboard + Paste urls from
  file (`pickFileProvider`, `_addDownloads` helper). Widget tests in
  widget_test.dart: menu lists items in order with dividers + submenu;
  clipboard paste adds per URL with rename policy + snackbar; no-URL
  clipboard → snackbar, no adds; file paste adds from a temp file;
  cancelled picker → nothing.
- M3: Export/Import submenu (Export all, Import downloads, Export/Import
  settings + `FileConflictSettings` exportJson/importJson + unit tests).
  Widget tests: export all writes all URLs; import downloads adds parsed
  URLs; export settings writes JSON; import settings valid/invalid.
- M4: About dialog + Quit (about_dialog.dart, app_info.dart,
  `quitAppProvider`). Widget tests: About shows name + version; Quit
  calls the overridden quit stub, menu closes.
- Gates per part: desktop `flutter test`, `flutter analyze` clean;
  release build once at M4 (runner unchanged).

## Verification (manual, by Tuấn Anh after re-running)

- Menu opens from the ☰ button, items in order, Export/Import opens the
  submenu.
- Paste 3 URLs from clipboard → 3 rows start; paste text with no URLs →
  'No valid URLs found'.
- Paste from a .txt file with URLs → rows added; cancel the picker →
  nothing.
- Export all → file lists every download URL; Import downloads → rows
  added.
- Export settings → file holds policy + recent dirs; Import settings →
  the New download dialog's Save to list follows the imported dirs.
- About shows name + version; Quit quits the app (tray icon goes away,
  process ends).
